## P0 — Critical (fix first)

### 1. Application authentication is a no-op

`lib/auth.ts` `requireAdmin()` always returns `true`. Comments claim network-level privacy. CI still hits the public DigitalOcean host `https://video-engine-ccfl-jpd37.ondigitalocean.app` (`.github/workflows/e2e.yml` `live-ui`).

Every `if (!(await requireAdmin()))` check is dead. Combined with missing gates on other routes, anyone who can reach the process can:

- Drive Claw (`POST /api/claw/chat`) — LLM spend, Resend mail, GitHub REST, Composio, Steel, E2B, Cursor spawn via Brain
- Write Bitdeer/NVIDIA keys (`POST /api/admin/nvidia/keys`)
- Upload/download conversation files (25 MB)
- Control Computer / Forge / Swarm

**Fix:** Restore real session + `ve_live_*` checks in `requireAdmin()`. Wire `AuthGuard` back to `/api/admin/session`. Reject unauthenticated API calls with 401. Do not treat “private droplet” as auth. Add unit tests that fail if `requireAdmin()` is a constant `true`.

### 2. Hardcoded admin unlock code

```5:18:lib/auth.ts
export const ADMIN_UNLOCK_CODE = "1234";
// ...
export async function requireAdmin() {
  return true;
}
```

`POST /api/admin/login` still accepts `1234` **or** `ADMIN_PASSWORD`. `.env.example` already flags this smell. Comments in `auth.ts` say the login route was removed; it was not.

**Fix:** Delete `ADMIN_UNLOCK_CODE`. Compare only against a server-side secret (hashed, not plaintext). Rate-limit login. If login stays unused, delete `app/api/admin/login/route.ts` instead of leaving a backdoor.

### 3. High-impact APIs never call `requireAdmin`

Even after (1) is fixed, these stay open unless gated:

| Route | Capability |
|---|---|
| `POST /api/cursor/launch` and `/api/cursor/*` | Spawn / steer / cancel Cursor cloud agents via Aion-Brain |
| `POST /api/swarm` `op=spawn\|run\|stop` | Start/stop swarm workers |
| `POST /api/computer` | Live Chromium (boot, type, upload, takeover) |
| `POST /api/forge` | Stealth browser sessions, scrape, screenshot |

**Fix:** Call `requireAdmin()` on every mutating route (and status routes that leak session cookies / screenshots). Cover with 401 tests.

### 4. VIDEO-Engine product contract is documentation-only

`AGENTS.md` and `README.md` still specify one-shot 8s generation (`hedra` \| `veo` \| `grok` \| `a2e`), `POST /api/v1/video`, `durationSeconds: 8`, `numberOfVideos: 1`, `ONE CONTINUOUS SHOT ONLY`.

`next.config.ts` documents the 2026-08-30 strip. There is no video job table, no Veo/Gemini client, no Grok Imagine client, no A2E start client. Hedra is **status-only** (`hedra_status` → `GET https://api.hedra.com/v3/models`). Image-gen flags remain but generation routes are gone.

**VEO 3.1 compatibility:** not a version-skew bug. The feature is missing. There is nothing to patch for Veo 3.1 until the generation path is restored under the one-shot contract.

**Fix (pick one, do not leave both):**

- **A — Restore VIDEO-Engine:** reintroduce `/api/v1/video` + provider clients + job persist/poll/download, keep one-shot 8s, update UI category cards; or
- **B — Honest Claw-only product:** rewrite `AGENTS.md` / `README.md` / `.env.example` / feature-flags / `claw-state` disconnect list to match the tree (Claw + Computer + Swarm + Forge + Integrations). Remove unused `GEMINI_API_KEY` / `A2E_API_KEY` / `IMAGE_GEN_ENABLED` claims.

### 5. Next.js critical RCE in lockfile

`npm audit` on installed tree:

- **critical** `next@15.5.23` — GHSA-p293-qw3h-jr36 (Windows RCE), GHSA-2xp9-vwfh-vxw4 (Image Optimization AVIF RCE). Range includes this version.
- **high** `postcss` (via Next) — sourceMappingURL file read / XSS stringify.
- **high** `sharp` — libvips / libheif CVEs.

The app uses `next/image` (`components/claw-logo.tsx` → `/claw-logo.jpeg`). Hosting is Linux (DigitalOcean), so the Windows RCE is lower likelihood; AVIF image-opt still applies if optimization is enabled (Next default).

**Fix:** `npm audit fix` (or pin Next to the first patched release outside `…-16.3.0-preview.10`). Rebuild and re-run typecheck + e2e. Do not leave `next@15.5.23` on a public host.

## P1 — High

### 6. Lint pipeline is a stub

`package.json` `"lint": "eslint ."` but eslint is not a dependency and there is no config. CI (`.github/workflows/e2e.yml`) runs typecheck + build + Playwright only — **not** lint, **not** unit tests.

**Fix:** Add `eslint` + `eslint-config-next` (or delete the script). Run `npm run lint` and `npm run test:unit` in `verify`.

### 7. NVIDIA key prefix leaked over HTTP

`GET /api/admin/nvidia/keys` returns `{ count, sample: keys[0].slice(0,12)+"…" }` after a no-op auth check.

**Fix:** Return `{ configured: boolean, count }` only. Never return key prefixes.

### 8. Settings UI invents key inventory

`app/settings/page.tsx` sets `keyCount: 11` in a comment (“pool count not exposed”). Misleading operator UI.

**Fix:** Use `/api/admin/nvidia/keys` `count` after (7) is sanitized.

### 9. Cursor integration is Brain-proxy only

Local `lib/cursor/cloud-agents.ts` was deleted in PR #55. CCFL forwards to Aion-Brain (`AION_BASE_URL` + `AION_API_KEY`). `CURSOR_API_KEY` on this host is name-only. Missing Brain → Trinity HOLD (`AION_UNCONFIGURED`). Unit tests mock Brain and assert CCFL never calls `api.cursor.com` (`tests/unit/cursor-cloud-agents.test.ts`).

This is complete **as a proxy**. It is incomplete **as a standalone Cursor client**. `.env.example` still says DigitalOcean already has `CURSOR_API_KEY` on the CCFL app — leftover from the old client.

**Fix:** Keep proxy. Document HOLD when Brain is down. Remove the implication that setting `CURSOR_API_KEY` on CCFL launches agents. Add `requireAdmin()` (see P0.3).

### 10. Auth stack is half-deleted

Present: `POST /api/admin/login`, `GET /api/admin/session`, `POST /api/admin/logout`, `sessions` table, `verifyApiToken()`.
Absent: `/login` page. `AuthGuard` is a transparent wrapper. `requireAdmin()` ignores cookies and `ve_live_*`.

**Fix:** Either finish the strip (delete login/session/logout/tokens) or finish auth (P0.1). Do not keep both.

### 11. Feature-flag / health docs describe deleted products

`lib/feature-flags.ts` still documents image-gen 410 responses, Reddit autopilot (`lib/reddit-research/*`), and Claw disconnecting Hedra/A2E/Gemini/OpenAI/Grok image gen. `GET /api/health/claw-state` lists those providers. None of those modules exist.

**Fix:** Delete dead flags or implement the modules. Trim `claw-state` to connectors that exist.

### 12. Model contract drift

`AGENTS.md` Claw default: `nvidia/nemotron-3.5-lightning-30b-a3b`.
Runtime registry (`lib/nvidia/models.ts`): Bitdeer `mistralai/Mistral-Large-3-675B-Instruct-2512` (agent default) and `zai-org/GLM-5`. `.env.example` matches Bitdeer, not Nemotron.

**Fix:** Update `AGENTS.md` to the Bitdeer enum (or restore Nemotron in the registry — do not leave both).
